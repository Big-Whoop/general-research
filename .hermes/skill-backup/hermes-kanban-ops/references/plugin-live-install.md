# Live-installing a repo plugin for testing

- Install = symlink `/opt/data/plugins/<id>` -> repo main checkout + add `<id>` to `plugins.enabled` in `/opt/data/config.yaml` (backup first, edit with sed, validate with yaml.safe_load). Merging to main changes the live plugin after the next restart.
- Verify LOAD in the real host, not by importing with the venv python: grep `/opt/data/logs/agent.log`, `gui.log`, `errors.log` for `Failed to load plugin <id>` AFTER the last start (`ps -o lstart= -p 1`), and for `Mounted plugin API routes: /api/plugins/<id>/`. Old tracebacks stay in the logs; compare timestamps, not counts. The venv has packages (e.g. PyYAML) that plugins do NOT get unless declared in `pyproject.toml [project].dependencies` (wins) or `plugin.yaml python_dependencies`; worker/reviewer tests in the venv miss this. Require an import-audit test (deptry with host modules ignored) on plugin cards.
- Plugin deps live in a per-selection env `/opt/data/installs/*/environments/<hash>/venv`. After consent + restart a NEW env dir appears; check it for the package (`ls …/site-packages | grep -i <pkg>`) to confirm the consent happened.
- Consent: `hermes plugins disable <id> && hermes plugins enable <id>` (interactive -> user runs it) + restart. Headless/CI: `hermes plugins install <git-url> --ref <sha> --enable --yes-deps`. Never run `--install-deps` in the live container: it installs into the live venv.
- hermes-suite restart (k3s ns/deploy `hermes-suite`) cannot be done from the pod: no kubectl, SA token unreadable (API: Unauthorized). Give the user: `kubectl -n hermes-suite scale deploy/hermes-suite --replicas=0 && kubectl -n hermes-suite scale deploy/hermes-suite --replicas=1`.
- Keep two separate checks per plugin repo: a repo-state gate (pytest, smoke, deptry, `doctor`/`validate` and `serve --port 0` in a temp `HERMES_HOME`) that never reads `/opt/data`, and a read-only live-health script (plugin enabled + no load error since last start). A gate that inspects the live install stays red for reasons the code cannot fix.
- Catalog readiness: `hermes plugins validate .` (same check as catalog CI). Fails on tools/hooks not in `provides_tools`/`provides_hooks`, security-scans the WHOLE repo tree (research docs quoting prompts flag as dangerous), warns on private core imports (rule 9). Submission = one PR adding `plugin-catalog/<id>.yaml` pinned to a 40-hex SHA; only the repo owner submits.
