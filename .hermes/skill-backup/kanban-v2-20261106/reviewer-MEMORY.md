Merge policy (user decision 2026-10-01, hardened 2026-10-06 after stale-base-repo incident t_4aa2143a): after an APPROVE verdict, the reviewer merges the PR ITSELF so dependent cards can run unattended: (1) post the PR comment with the verdict, (2) `gh pr merge <PR#> --repo <owner/repo> --squash` (or --merge; --squash preferred), (3) pull the BASE repo (the board's default_workdir, e.g. /workspace/dev/repos/ours/llama-swap) so child worktrees branch from fresh master AND VERIFY: `git -C <base-repo> pull --ff-only`, then IMMEDIATELY `git -C <base-repo> log -1 --format=%H` — the resulting SHA goes into BOTH the PR verdict comment and the kanban summary. If the pull FAILS (e.g. local uncommitted exempt-docs): run `git diff --stat`; if the changes are exempt, commit them and `git merge origin/master` (NOT --ff-only — local commit diverged), then take the SHA. (4) ONLY THEN kanban_complete with summary including 'PR #N merged, base repo updated to <sha>'. GATE CASE: if kanban_complete is blocked at the PR-acceptance gate, the pull is STILL DONE (it stands before complete) — the block summary MUST include the base-repo SHA so the main session can read the pull status from the block text. If the merge fails (conflict, CI red), do NOT complete: post the failure to the PR, kanban_block the card with kind=needs_input and the concrete reason. NOTE — PR-acceptance gate on PRIVATE repos without GitHub Pro: unusable (permanent). `gh api repos/<repo>/rules/branches/<branch>` returns 403 ('Upgrade to GitHub Pro or make this repository public') and the gate classifies the 403 as 'infra', refusing kanban_complete forever. For boards with private repos without CI, set the completion contract to local-only; the reviewer verifies the merge via `gh pr view --json state,mergedAt,mergeCommit` and takes that evidence into the summary. The human merge gate no longer exists for reviewed cards; the user reviews PRs on GitHub as an audit trail.
