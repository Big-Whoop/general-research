# Lane L3 — X2Go "Published Applications" (RemoteApp-style) — SQ4 + SQ6
Probe/maintenance checks performed: 2026-10-25T14:23Z (UTC).
Environment assumed: client CachyOS/Plasma 6 Wayland; server Ubuntu/Kubuntu 24.04 (possibly headless); LAN primary.

## Findings

1. Published Applications is X2Go's RemoteApp-like mode: server-side menu of apps whose windows "integrate into your local desktop environment like it was locally installed" — source: https://wiki.x2go.org/doku.php/wiki:advanced:published-applications (official) — quote: "makes it possible to display a menu with a list of the available remote applications for the user, which when started behaves like a locally installed application. The menu with the applications can be controlled centrally, and can be system-wide or per user." — Tier: Verified.

2. Server admin defines published apps via .desktop files in /etc/x2go/applications/ (a symlink to /usr/share/applications by default) — source: same official wiki page — quote: "On the X2Go Server you can control the applications displayed on the Published applications menu by adding, removing or controlling access to the files in /etc/x2go/applications/. **Note that this is by default a symlink to /usr/share/applications!**" Corroboration (Arch): "This location however is not created by default and can be created by creating a symlink to /usr/share/applications/" (https://wiki.archlinux.org/title/X2Go, community/distro-doc). Restricting which users may run an app = filesystem permissions (bug #1465: "you have to use *filesystem permissions*... setting chmod 750 or 550 on the particular application", https://bugs.x2go.org/cgi-bin/bugreport.cgi?bug=1465, official tracker). — Tier: Verified.

3. Client UX: a "Published applications" session profile; the app list is fetched from the server through the session; tray-icon right-click gives a compact app menu; each launched app behaves like a local app — source: official wiki published-applications page — quote: "The list that is presented looks as if it was locally stored, but it's actually fetched from the server through the session... it integrates into your local desktop environment like it was locally installed." and "right-clicking the X2Go icon and selecting the name of your session will show the list of published applications as well". Note: an x2goclient main/tray window keeps running (ServerFault: "I believe you still have the connection GUI open somewhere", https://serverfault.com/questions/674176/remoteapp-seamless-rdp-linux-server, community). — Tier: Verified.

4. Per-app window mechanism: each remote app window is mirrored as its own ("clone") window on the client X server, with an agent-side window-id mapping; suspend closes only the local clones (session state kept server-side in SQLite, state tracked by x2gocleansessions) — sources: https://lists.x2go.org/hyperkitty/list/x2go-user@lists.x2go.org/thread/7FYT2DEKYZDUUQO5S556WJZCGDRTDAHZ/ (official mailing-list; page fetch was Anubis bot-walled, quote from search index) — quote: "Whenever a published application opens a window it will open this window on the x2goagent/nxagent on the server AND open a clone window on you local X server. Internally the agent has a mapping between the window ids of each window pair." + suspend/resume per ArchWiki (community/distro-doc): "you can leave a session on one client and reopen it even from another client at the same point. The session data are stored and administered in a SQLite database on the server". — Tier: Plausible (list thread read only via snippet; suspend/resume itself Verified via ArchWiki).

5. Mechanism/prereqs: X2Go tunnels NX over SSH; "The protocol is tunneled through the Secure Shell protocol, so it is encrypted" (ArchWiki); NX proxy + image compression with many codecs and quality 0–9, link profiles modem→lan — sources: https://wiki.archlinux.org/title/X2Go (community/distro-doc); https://manpages.debian.org/bookworm/pyhoca-cli/pyhoca-cli.1.en.html (official man page) — quote (pyhoca-cli man, NX compression methods): "nopack, 8, 64, 256, 512, 4k, 32k, 64k, 256k, 2m, 16m ... 16m-jpeg-% ... 16m-png-% ... 16m-rgb-%, 16m-rle-%"; x2goclient man: "--link Set default link type (modem,isdn,adsl,wan or lan, default: adsl)... --pack Set default pack method (default: '16m-jpeg')... --quality Set default image quality(0-9, default: 9)". "Well suited for low bandwidth connections" (https://www.howtoforge.com/tutorial/x2go-server-ubuntu-14-04/, community). Versus plain `ssh -X` (uncompressed X protocol, no image codec, no session suspend): expect a decisive X2Go win on WAN — inference from documented mechanism, not a measured benchmark. — Tier: Verified for mechanism; Speculative for the head-to-head magnitude.

6. Headless server OK for single apps: "X2Go can forward the windows of a single application to your computer, without the desktop environment, similar to traditional X11 forwarding... choose Published Applications and connect" (https://pages.github.nceas.ucsb.edu/NCEAS/Computing/remote_access_using_x2go.html, institutional practice); "Instead of a whole desktop session, you can launch single graphical applications in X2Go" (https://www.digitalocean.com/community/tutorials/how-to-set-up-a-remote-desktop-with-x2go-on-debian-8, community). Still needs `x2goserver-xsession` (session launcher) plus a WM/DE binary available for the agent session; ArchWiki documents PATH/dbus-launch pitfalls when starting desktops via SSH. — Tier: Plausible.

7. Ubuntu 24.04 server packages: x2goserver 4.1.0.6-1.1build1 IS in Ubuntu 24.04 (noble) **universe** (uploaded 2024-04-22; binaries include x2goserver, x2goserver-x2goagent, x2goserver-xsession, x2goserver-printing, cups-x2go) — source: https://launchpad.net/ubuntu/noble/+source/x2goserver/ (official distro package index) — quote: "Current version: 4.1.0.6-1.1build1, Uploaded: 2024-04-22". Official PPA ppa:x2go/stable also lists Noble (24.04) in its published series (https://launchpad.net/~x2go/+archive/ubuntu/stable, official PPA, quote: "sudo apt-get install x2goserver x2goserver-xsession"; last PPA upload burst 2024-03-27, "0 updates added during the past month"). Official install doc: https://wiki.x2go.org/doku.php/doc:installation:x2goserver. Caveat: universe/PPA versions are the 4.1.0.6 (2023-era) release. — Tier: Verified.

8. Client packaging: Ubuntu → x2goclient in ppa:x2go/stable and Rob Savoury's backports PPA with Noble build "Noble (4.1.2.3-3~24.04.sav0)" (https://launchpad.net/ubuntu/+source/x2goclient, official index). Arch/CachyOS → **no official Arch package**; x2goclient 4.1.2.3-1 lives in AUR (19 votes, not flagged out-of-date, PKGBUILD last modified 2025-06-11; deps qt5-x11extras, nxproxy, libssh) and x2goserver 4.1.0.6-1 AUR flagged **out-of-date 2026-01-24** — sources: https://aur.archlinux.org/rpc/v5/search?arg=x2go and https://aur.archlinux.org/rpc/v5/info?arg[]=x2goclient (package metadata), https://wiki.archlinux.org/title/X2Go ("Two parts are available... x2goserver AUR ... x2goclient AUR"). — Tier: Verified.

9. Client on Wayland: x2goclient (Qt5) crashes/fails when connecting from a Wayland session — official bug #1414 "X2Goclient crashes on plasma on Wayland, on plasma on xorg it works fine" (https://bugs.x2go.org/cgi-bin/bugreport.cgi?bug=1414; reported 2019, still open — tracker shows only spam activity in 2023–24; a patch "Select X11 backend on wayland" was posted 2019, and Debian grave bug #1042816 "x2goclient segfaults during connect under Wayland" was later marked done). Documented workaround: force xcb/XWayland — ArchWiki quote: "This problem is usually caused by Qt on Wayland... change the lines starting with Exec=x2goclient to Exec=env QT_QPA_PLATFORM=xcb x2goclient". Official de-compat page is noncommittal: "X2Go Client should be able to run under any and every X11-based desktop environment. Wayland-based desktop environments need testing." (https://wiki.x2go.org/doku.php/doc:de-compat, official). — Tier: Verified (crash + workaround documented in ≥2 independent official/distro sources).

10. Server-side session quality limits: X2Go's X server is nxagent, "forked from the X.org 6.9 codebase (from 2005) feature-wise"; no Xcomposite; GLX only 1.2 (workaround page exists) — "X2Go does not support GLX 1.4 which is required for many graphical applications, including Firefox" (ArchWiki). DE compatibility (official de-compat page): XFCE/LXDE/MATE fine; "KDE 5 now works with X2Go, even though it takes a long time to initialize"; GNOME 3.12+ "probably not compatible"; LXQt "Incompatible due to Qt5 incompatibility". For published-apps mode this mostly limits in-app GL; pick simple apps accordingly. — Tier: Verified.

11. Clipboard: bidirectional, configurable — x2goclient man: "--clipboard=<both|client|server|none> Set default clipboard mode" (https://manpages.debian.org/bookworm/x2goclient/x2goclient.1.en.html, official man page). Text/image clipboard; NOT clipboard file-copy — file exchange is a separate feature (next item). — Tier: Verified.

12. File transfer: client→server folder sharing via SSHFS/FUSE; server mounts client dirs under ~/media; requires sshd X11-forwarding-friendly config and fuse module — ArchWiki: "local directories could be shared. The server will use fuse and SSHFS to access this directory and mount it to a subdirectory media of your home directory on the server... 'Check fuse kernel module is loaded'" + man "--client-ssh-port Local ssh port (for filesystem export, default: 22)". Server→client reverse sharing is not in these docs (only via broker in newer releases; unverified here). — Tier: Verified (client→server direction).

13. Audio: opt-in PulseAudio redirection to the client: "--sound ... not enabled by default. --sound-system ... arts, esd, pulse (default: pulse)" (x2goclient man, official). With PipeWire: no official x2go statement found. Community data point (2022): Debian #1024093 "pipewire: Upgrade to pipewire 0.3.60-1 breaks sound... When run via x2go, videos would not play at all" (https://groups.google.com/g/linux.debian.bugs.dist/c/M-cLfUtfJq8/m/zWVRJ-NDBwAJ). Since x2go speaks the PulseAudio protocol on both ends, PipeWire's pulse-compat layer is the expected glue on a PipeWire client (CachyOS) — reasonable but unverified here; treat audio as the flakiest feature (x2go's own ArchWiki advice: "In case of performance issues... try to turn off sound support, printing support and file share tunneling"). — Tier: Plausible (works generally), Speculative (PipeWire-specific).

14. Printing: client-side printers are exposed into the session via CUPS integration — official usage manual: "The last point in this tab enables the client side printing support to let you print locally from the remote side" (https://wiki.x2go.org/doku.php/doc:usage:x2goclient); implementation packages exist: cups-x2go + x2goserver-printing published in the official PPA and Ubuntu noble (Launchpad package lists above). — Tier: Verified (feature + packaging); Plausible (zero-friction today).

15. Latency/UX knobs: keyboard shortcut grab (Ctrl+Alt+G) to avoid Alt+Tab conflicts; keystrokes config /etc/x2go/keystrokes.cfg (official usage page). NX session resuming means a dropped WAN link costs a reconnect, not lost work — ArchWiki suspend/resume quote above. Quirk: suspending mid-process-launch can degrade server perf; mitigation documented: add "X2GO_NXOPTIONS=\"sleep=0\"" to /etc/x2go/x2goagent.options (ArchWiki). Session logoff bugs (ArchWiki, bug #914) and iproute2/ss regression affecting the session-picker (bug #799) are recorded pitfalls; SSH config with tokens (%d/%L) breaks x2goclient's option parsing ("Couldn't apply options", ArchWiki). — Tier: Verified.

## SQ6 — Day-to-day start path & KDE start-menu icon (documented mechanics)

18. Official CLI building blocks for per-app launching (all Verified, official man page https://manpages.debian.org/bookworm/x2goclient/x2goclient.1.en.html):
    - "--autostart=<app> — Launch <app> by session start in \"published applications\" mode. This parameter should go along with --session=<session-profile-name>, where the given session profile should be configured as a session profile of type \"Published Applications\"."
    - "--session=<session-profile-name> — Pre-selection of a session profile (by its session profile name) at client startup."
    - "--hide — Hide client (start hidden)"; "--close-disconnect — Close X2Go Client after a session got disconnected"; "--tray-icon — Show tray icon... forces the tray icon to be shown in hidden X2Go Client mode"; "--no-session-edit"; "--session-conf=<file> — Path to alternative session profile config (default: $HOME/.x2goclient/sessions)".
    - Key auth, no prompts: "--autologin — By default, search for standard SSH key file names or try using an SSH agent"; "--ssh-key=<file>"; "If a priv SSH key has been specified, skip the autologin procedure" (bug #222 changelog, official tracker).
    - Single-app-per-profile is by design: bug #1024 "the existing x2goclient --autostart option only allows one app to be specified to be autostarted" (https://bugs.x2go.org/cgi-bin/bugreport.cgi?bug=1024) → one profile+shortcut per app is the intended pattern.
    - Scripted alternative without the Qt GUI: pyhoca-cli "aims to be a cross-platform... X2Go command line client written in Python... You can use it for scripting remote X2Go sessions... parsing x2goclient configuration files", actions "-N/--new, --try-resume, -c/--command <CMD>" (official man page).
    - Wayland desktop-entry pattern (Verified, ArchWiki): wrap Exec as `Exec=env QT_QPA_PLATFORM=xcb x2goclient ...`.

19. No feature found that auto-creates KDE start-menu entries for published apps: x2goclient shows the server-provided app picker inside its own window/tray; no official doc mentions client-side .desktop generation for published apps. Therefore the start-menu icon is **user-authored .desktop files** composing the verified options above. Assembled recipe (recipe = Speculative as a whole; every flag is Verified):
    ```
    # ~/.local/share/applications/x2go-<app>.desktop
    [Desktop Entry]
    Type=Application
    Name=Remote <App>
    Exec=env QT_QPA_PLATFORM=xcb x2goclient --session=pubsrv --autostart=<app> --hide --close-disconnect
    Icon=.../session-icon.png   # client supports --session-icon / custom icons
    StartupNotify=false
    ```
    with one "Published Applications"-type profile `pubsrv` pre-created (host, user, SSH key for passwordless auth, clipboard=both, sound as desired, folder sharing as desired) in ~/.x2goclient/sessions; no terminal popup since it is a GUI Exec. pyhoca-cli -P pubsrv --new --try-resume -c <app> is the documented scripting alternative.
