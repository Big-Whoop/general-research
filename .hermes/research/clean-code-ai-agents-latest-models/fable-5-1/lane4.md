## TL;DR

1. **The strongest hands-on code-quality evidence is Huntress (22 Sep 2026): Fable 5.1 hand-rolls what the framework provides (API recall ~48% baseline, best-in-class but low), slop compounds through codebase precedent, and a 4-line CLAUDE.md rule + a second-model Stop-hook reviewer took it to 28/28 at ~$0.30 more per task.** [P-01]
2. **Over-building is now quantified by a harness vendor against its own interest: Cognition/Devin's FrontierCode `scope` criterion penalizes any diff touching files outside the task, and Fable 5.1's score peaks at medium effort and falls below Fable 5 at higher reasoning efforts because it "more often adds unrequested changes outside of the task."** [P-03]
3. **Code-review noise dropped sharply: CodeRabbit's 45-task eval found recall flat (61.0% vs 61.9%), precision +4.5 pts, total comments −34%, nitpicks −70%, latency +48.7%; Low effort beat High on recall.** [P-02]
4. **Cost: Fable 5.1 is cheaper per task than Fable 5 and Opus 5 on cache-heavy agentic work (Devin: $2.68 vs $5.84/$3.51 per FrontierCode task; 33% fewer tokens than Opus 5) but more expensive per task at max effort on hard reasoning (Artificial Analysis: ~20% above Fable 5, 1.7× output tokens, $3.69/task).** [P-03, P-06, P-07]
5. **Long runs: partner-reported 38-hour unattended ML run (Ramp) and 3-day prototype (MongoDB); Every ran it "for days" and reports over-delivery (unrequested subagents, ignored interruptions, exceeded word/quote limits) concentrated at xhigh/max effort.** [P-08, P-04]
6. **GitHub: 469 issues in anthropics/claude-code mention Fable 5.1. Recurring themes: launch-day version gate (stable Claude Code rejected `claude-fable-5-1` with a 400; workaround = spoofed User-Agent, found by the model itself), safeguard false positives (`reasoning_extraction`), silent downgrade to Opus 4.8, quota burn at low effort, and Extra-High runaway behavior. A reverse-engineered Claude Code 2.1.257 binary shows Anthropic injects an explicit scope-discipline prompt ("The requested scope is the deliverable — don't quietly narrow, widen, or transform it") and a writing-style prompt into Fable 5.1's system prompt.** [P-10…P-18]

## Findings

### P-01 — Huntress: Fable 5.1 hand-rolls framework APIs (48% API recall); a 4-line rule + second-model Stop-hook reviewer reach 28/28 at ~$0.30/task more [P3 DRY, P5 YAGNI, P8 gates] — KEY
- Claim: In a controlled eval on a real Rails 8.1 codebase (Fable 5.1 at default effort via Claude Code, 264 trials across rounds), Fable 5.1's baseline API recall was ~48% (10/21) — best among frontier models (Rails' "Agents on Rails" benchmark: 41.3% for Fable 5.1 vs 34.9% Opus 5, 25.4% Sonnet 5) but low; a four-line "prefer framework APIs, check the installed gem before writing a helper" rule in CLAUDE.md raised it to 86% (p=0.008), and a Claude Code Stop hook that sends the finished diff to a second model (Sonnet 5) and blocks with exit 2 on "REWORK" closed the remaining gap to 28/28 across all seven tasks at about 30 cents more per task on Fable 5.1.
- Source: https://www.huntress.com/blog/claude-fable-api-recall (engineering blog, Huntress security company, Max Rogers). Date: "Published: September 22, 2026". Read in full.
- Verbatim: "When Huntress tested Anthropic's Claude Fable 5.1 in evaluations, we started with a ~48% accuracy baseline for API recall: significantly more than previous models but still pretty low. With three small changes to our coding harnesses, we got it to 100% accuracy across seven of our eval tasks." / "Our coding agent greps the codebase, finds a hand-rolled version of the same thing/pattern, and copies it. One of our token generators lives in a few models because one person wrote it and two AI-assisted pull requests ended up copying it. Our eval benchmark copied it another time. Every handrolled helper that lands becomes more precedent for the next coding agent to imitate." / "The popular checklist (pin the version, read `db/schema.rb` first, prefer `pluck`) made the agent faster and worse; it never ran RuboCop and shipped an autocorrectable layout offense on three otherwise correct solutions. Optional items got ignored. A skill sitting in `.claude/skills` with a description naming the exact situation was never invoked by the coding agent (unfortunately)." / "A rule can only help with slop the agent recognizes as slop." / "28 of 28 across all seven tasks, every solution passing, at about 30 cents more per task on Fable 5.1"
- Tier: **Verified** (primary source read in full; controlled paired evals with pre-registered decision rules and McNemar tests; small n — 7 tasks, author flags "limited test... pretty small sample size"). Verdict evidence: P3 AMPLIFIED (reuse need) / INVERTED default (hand-rolling is the failure); P8 independent gate AMPLIFIED (second-model reviewer: 24 wins, 0 losses); P2 rules file works only for recognized slop; optional skills ignored (progressive disclosure does not transfer to Claude Code skills).

### P-02 — CodeRabbit: Fable 5.1 reviews with flat recall, +4.5 precision, −34% comments, −70% nitpicks, +48.7% latency; Low beats High [P10, P4/P5] — KEY

- Source: https://www.coderabbit.ai/blog/fable-5-1-model-review (vendor engineering blog, CodeRabbit AI code review, Juan Pablo Flores & Gowtham Kishore Vijay). Date: "September 01, 2026". Read in full.
- Verbatim: "Fable 5 was a thorough model that spent a long time exploring before it acted. That helped on larger coding tasks, but its reviews were slow and produced more comments than we wanted. Fable 5.1 keeps the same habit of checking the environment and planning first, while showing more restraint in what reaches the final review." / "The result was still noisy because 37.3% precision means most final comments were not marked valid. - Tier: **Verified** (primary source read in full; n=45 tasks/105 issue points; cross-snapshot caveat flagged by authors — "The two evaluations used different versions of our review system, so the comparison shows direction rather than a same-day, head-to-head result"). Verdict evidence: P10 comment-noise MOOT trend (nitpicks −70%); P4/P5 scope restraint improved vs Fable 5; P8 independent validation still required (37.3% precision).

### P-03 — Cognition/Devin: Fable 5.1 cheaper per task than Opus 5 on end-to-end work, and its score falls at higher effort because it adds unrequested changes [P4/P5, cost] — KEY
- Claim: On Cognition's FrontierCode 1.1 Extended benchmark (code mergeability), Fable 5.1 costs $2.68 per task at score 63.6 vs Fable 5 $5.84 (62.8) and Opus 5 $3.51 (63.6); a typical task reads ~3M cached tokens (>95% of all tokens are cache reads) and Fable 5.1 takes 33% fewer tokens than Opus 5 — but because their mergeability criteria include a `scope` criterion that penalizes "any diff touching files outside of what the task requires, even if the diff is correct or useful," Fable 5.1's score peaks at medium effort and falls below Fable 5 at higher reasoning efforts.
- Source: https://devin.ai/blog/fable-5-1 (vendor engineering blog, Cognition/Devin). Date: `datePublished: 2026-08-31` (one day before public launch; early-access post). Read in full.
- Verbatim: "Fable 5.1 now costs less than Opus 5 on end-to-end tasks." / "We found that on FrontierCode, Fable 5.1 takes 33% fewer tokens to complete the same tasks relative to Opus 5." / "A typical FrontierCode task on Fable 5.1 reads about 3 million cached tokens, writes about 21 thousand output tokens, and reads only about 70 thousand tokens of uncached input. ... Over 95% of the tokens on both models are cache reads." / "On this benchmark, Fable 5.1 does not strictly score higher as thinking increases. The reason is our mergeability criteria. One of the criteria is `scope`. It works against any diff touching files outside of what the task requires, even if the diff is correct or useful. This could be an extra docstring, updated docs, a new CI job where an existing one could have been reused, etc. This is why Fable 5.1's score peaks at medium and falls below Fable 5 at higher reasoning efforts. Its pass rate continues to rise with effort, but at higher reasoning efforts it more often adds unrequested changes outside of the task."
- Tier: **Verified** (primary source read in full; vendor self-interest on the cost claim, but the scope-creep finding works against their own model's headline and is a direct quantification of over-building on Fable 5.1). Verdict evidence: P4/P5 INVERTED, now measured as a benchmark penalty that grows with effort; cost-per-task (not per-token) is the right unit; cache-read economics dominate agent cost.
